# 동아리 행사 예산 점검

행사 회계·구매·참가 CSV를 읽어 **재원별(학교지원금/동아리회비) 잔액·순지출**과
**확인 필요 지출**, **정원**, **구매계획 인원별 비용**을 정리한다. 원본 CSV는 절대 수정하지 않는다(읽기 전용).
AI가 판단하지 않는다. 판단 규칙은 아래에 고정하고, 계산·검사·저장은 `scripts/budget_check.py`가 한다.

## 근거 문서

집행·집계 판단은 문서 ID와 조항으로 근거를 남긴다.

- **RULE-01** 학교지원금 지침 — 지원 대상/제외(제3조)·증빙과 용도(제4조)·자금 구분(제5조)
- **RULE-02** 공간·정원 규정
- **ACCOUNT-01** (W04_08 회계기준) — 기간·기초잔액(제1조), 부호(제2조), 잔액·순지출 공식(제3조), 판단(제4조), 구매계획(제5조)
- **APPROVAL-FUND-04** (W04_05) — 지원금 승인서: 총 한도 1,500,000 / 1차 지급 1,000,000(거래 T091)
- **APPROVAL-SPACE-04** (W04_06) — 장소 사용 승인서: 최초 승인 정원 160
- **CHANGE-SPACE-04** (W04_09 정원변경승인서) — 승인 정원 **160 → 180**으로 변경. `APPROVAL-SPACE-04`의 정원 조항을 **대체**한다.

## 집계 규칙 (고정)

### 1) 기초 잔액과 부호 (ACCOUNT-01 제1·2조)
- 기초 잔액: 학교지원금 **0원**, 동아리회비 **800,000원**.
- 부호: 수입·환불입금은 **(+)**, 지출·환불지급은 **(−)**. 금액은 양의 정수 원 단위.

### 2) 재원별 현재 잔액 (ACCOUNT-01 제3조)
- 재원별 잔액 = 기초잔액 + 수입 + 환불입금 − 지출 − 환불지급.
- 학교지원금 잔액은 **실제 입금된 금액(1차 1,000,000, T091)** 기준으로 계산한다.
  승인만 되고 미입금인 잔여 500,000원은 현재 현금에 더하지 않는다(RULE-01 제5조).

### 3) 순지출 (ACCOUNT-01 제3조)
- 행사 순지출 = 지출 + 환불지급 − 환불입금. **수입은 순지출에서 제외**한다.
- 재원별 순지출과 전체 순지출을 함께 낸다. 수입을 포함한 순현금흐름과 구분한다.

### 4) 확인 필요 지출 (RULE-01 제3·4조)
학교지원금 지출 중 다음은 보류로 표시하고 사유를 남긴다(임의로 인정하지 않는다).
- 용도가 빈칸이거나 불명확('인화비' 등) → 확인 필요(제4조)
- 증빙이 '없음' → 확인 필요(제4조)
- 항목/용도가 기념품·개인 선물·주류·회원 개인 장비 → 지원 제외(제3조)

### 5) 정원 (RULE-02 / 승인서)
- 승인 정원은 **CHANGE-SPACE-04에 따라 180명**이다(APPROVAL-SPACE-04의 160을 대체).
- CHANGE-SPACE-04는 **예산 증액이 아니며, 신청자 상태를 자동 변경하지 않는다.** 확정 인원은 참가신청 CSV의 '확정' 수 그대로 유지한다.
- 확정 인원이 승인 정원을 넘으면 `정원_초과`를 참으로 표시한다.

### 6) 구매계획 시나리오 (ACCOUNT-01 제5조)
- 수량기준 '참가자' → 수량 = 인원 × 계수. '고정' → 수량 = 계수.
- 비용 = 수량 × 단가. 재원별 합계와 총비용을 낸다.
- 구매계획은 **앞으로 필요한 수량 계산**이며 회계 거래·기지급 비용에 합산하지 않는다(제4조).
- 인원 시나리오: 140(확정 인원)·160(최초 승인)·180(현재 승인 정원).

값이 규칙에 없는 형태이거나 판단이 애매하면 추측하지 말고 `확인_필요_지출` 또는 관련 `참고`에 사유와 함께 남긴다.

## JSON 항목 (고정)

| 항목 | 자료형 |
|---|---|
| 행사 | 문자열 |
| 생성일 | 문자열(YYYY-MM-DD) |
| 읽은_행수 | 객체 `{파일명: 정수}` |
| 참가상태별_인원 | 객체 `{상태: 정수}` |
| 정원 | 객체 `{승인_정원, 확정_인원, 정원_초과(불리언), 근거, 참고}` |
| 학교지원금 | 객체 `{기초잔액, 총_승인_한도, 실제_입금, 미입금_잔여, 지출, 환불입금, 순지출, 현재_잔액, 확인_필요_지출(목록), 근거}` |
| 회비 | 객체 `{기초잔액, 수입, 환불입금, 지출, 순지출, 현재_잔액, 근거}` |
| 행사_순지출 | 객체 `{총_지출, 총_환불입금, 순지출, 학교지원금_순지출, 회비_순지출, 근거}` |
| 구매계획_시나리오 | 객체 `{인원라벨: {인원, 재원별_합계, 총_비용, 라인(목록)}}` |
| 근거문서 | 객체 `{문서ID: 설명}` |

항목 이름·개수·자료형을 매번 동일하게 유지한다. 확인_필요_지출의 각 원소는 `{거래_ID, 항목, 용도, 금액, 증빙, 사유(문자열 목록)}`.

## 실행 절차

CSV 읽기·규칙 적용·검사·저장은 `scripts/budget_check.py`가 한다.
스키마를 만족할 때만 저장하며, 항목 누락·추가나 자료형 오류가 있으면 저장하지 않고 사유를 알린다.

1. `data/`에 CSV 3개를 둔다: `회계내역.csv`(거래_ID,거래일,행사_ID,재원,유형,항목,용도,금액,증빙,원거래_ID), `구매계획.csv`(항목_ID,물품,수량기준,계수,단가,예정재원,용도), `참가신청.csv`.
2. 스크립트로 집계·검사·저장한다. Python 3.9 이상, 표준 라이브러리만 사용한다.

```bash
cd scripts
python3 budget_check.py            # data/ 기본 경로에서 읽고 submissions/E04예산점검.json 저장
python3 budget_check.py --event E04 --data <데이터폴더> --out <출력.json>
```

결과 JSON은 프로젝트 `submissions/` 폴더에 저장한다(스킬 폴더에 저장하지 않는다).
기존 산출물(`E04집계.json` 등)을 덮어쓰지 않도록 기본 출력명은 `E04예산점검.json`이다.
