2. 지난주 DAG의 정기 실행 연결

강사 화면에서 W05의 기존 창고 재고 집계 작업을 엽니다. Task Runner 우측 상단의 정기 실행을 선택하고, 스케줄 화면의 Details에서 작업 메시지, 실행 간격, 담당 에이전트를 확인하고, 이 작업의 승인 항목을 자동승인으로 선택해 저장합니다. 수동 승인 상태에서는 파일 읽기·쓰기 도구의 승인을 기다리며 스케줄이 멈출 수 있습니다. 아래의 최소 컨텍스트도 살펴봅니다. 메시지와 입력 파일만으로 수행할 수 있는 작업은 이 설정을 켜고 ON 상태인지 확인합니다. 에이전트는 계속 실행되지만 저장된 메모리·학습 내용·스티어링·스킬·이전 세션 기록을 불러오지 않아, 이전 맥락을 읽는 비용을 줄입니다. 스킬이나 저장된 맥락에 의존하는 작업은 끔(OFF)으로 둡니다.

계산 방식이 정해진 집계는 에이전트 대신 스크립트를 직접 실행하도록 만들 수도 있습니다. AI에게 스크립트를 만들게 한 뒤, 반복 실행은 그 스크립트에 맡길 수 있습니다. 다음 단계에서는 모임 신청 현황을 점검하는 에이전트 스케줄을 직접 만듭니다.

3. 스케줄 뷰에서 신청 현황 점검 만들기

스케줄 작업이 내 자료를 찾을 수 있도록 week06 폴더의 전체 주소(절대경로)부터 확인합니다. 폴더 이름이 같아도 저장 위치는 사람마다 다릅니다.

3-1. 내 week06 폴더 찾고 경로 복사하기

파일 탐색기나 Finder에서 실습 자료를 저장한 폴더를 엽니다. 위치가 기억나지 않으면 다운로드 또는 바탕 화면부터 확인하세요. ZIP으로 받았다면 먼저 압축을 풉니다.

실습 저장소 안에서 다음 폴더를 차례로 엽니다.

class → kookmin-2026-2 → ai-platform-development → week06

week06 안에 시작하기.html 파일과 practice 폴더가 보이면 맞게 찾았습니다. 아래에서 자신의 컴퓨터에 맞는 항목을 펼쳐 따라 하세요.

Windows · 경로 복사하고 PowerShell 열기
  1. 파일 탐색기에서 찾은 week06 폴더를 열어 둡니다.
  2. Alt + D를 누르면 위쪽 주소 표시줄에 전체 경로가 선택됩니다. Ctrl + C로 복사합니다. C:\ 또는 D:\처럼 시작하는 폴더 주소입니다.
  3. 작업 표시줄의 시작에서 PowerShell을 검색해 실행합니다. 열린 창에서 아래 3-2를 진행합니다.
Mac · 경로 복사하고 터미널 열기
  1. Finder에서 찾은 week06 폴더를 열어 둡니다.
  2. ⌘ + ↑로 한 단계 위로 이동한 뒤 week06 폴더 자체를 한 번 클릭해 선택합니다. 안에 있는 파일을 선택하지 않습니다.
  3. ⌥ + ⌘ + C(Option + Command + C)로 폴더의 전체 경로를 복사합니다. 보통 /Users/로 시작합니다.
  4. ⌘ + Space를 누르고 터미널을 검색해 실행합니다. 열린 창에서 아래 3-2를 진행합니다.

3-2. cd로 이동하고 pwd로 확인하기

다음 명령은 PowerShell 또는 터미널 창에 입력합니다. cd는 작업할 폴더로 이동하는 명령, pwd는 지금 있는 폴더의 전체 경로를 보여 주는 명령입니다.

  1. cd ""를 입력하고 두 큰따옴표 사이에 방금 복사한 경로를 붙여 넣습니다. Windows는 Ctrl + V, Mac은 ⌘ + V로 붙여 넣습니다. 큰따옴표는 경로에 공백이 있어도 하나의 주소로 읽게 해 줍니다.
  2. 완성된 cd "실제 경로" 명령에서 Enter를 누릅니다. 별도 메시지 없이 다음 입력 줄이 나와도 정상입니다.
  3. 이어서 pwd를 입력하고 Enter를 누릅니다. 출력된 경로의 마지막 폴더가 week06인지 확인합니다.

입력 모양 예시 — 아래의 minji와 저장 위치는 예시입니다. 반드시 앞에서 복사한 자신의 경로를 사용하세요. 두 명령은 한 줄씩 실행합니다.

Windows PowerShell 예시
cd "C:\Users\minji\Downloads\nxt-kirocrew-hands-on\class\kookmin-2026-2\ai-platform-development\week06"
pwd

Mac 터미널 예시
cd "/Users/minji/Downloads/nxt-kirocrew-hands-on/class/kookmin-2026-2/ai-platform-development/week06"
pwd

출력에서 경로만 복사하세요. PowerShell의 Path 제목과 밑줄, 입력 줄의 PS …>나 $ 표시는 제외합니다. cd에서 “경로를 찾을 수 없음”이 나오면 파일 탐색기나 Finder에서 폴더 경로를 다시 복사해 넣습니다. pwd만 실행하면 터미널을 처음 열었을 때의 폴더가 나올 수 있으므로, 먼저 cd로 이동하세요.

Windows에서 명령 프롬프트(cmd)를 열었다면

위 안내는 PowerShell 기준입니다. cmd에서는 pwd 대신 cd만 입력하면 현재 경로가 나옵니다. 폴더 이동은 드라이브까지 바뀌도록 cd /d "복사한 경로"를 사용합니다.

5. 사용자 지정 차단 규칙 등록하기

정규식(Regular Expression)은 문자열에서 특정한 모양을 찾는 규칙입니다. 검색창에 번호 하나를 넣으면 그 번호만 찾지만, 정규식으로는 “숫자 6개 뒤에 숫자 7개가 오는 형태”를 한꺼번에 찾을 수 있습니다. 여기서는 그 형태가 명령문에 들어 있으면 실행을 차단하도록 설정합니다.

설정 → 보안 → 거부된 명령 → 사용자 지정 차단에서 아래 규칙을 등록합니다.

이 규칙 읽어 보기
  • [0-9]{6}: 0~9 사이의 숫자가 6개 연속으로 나옵니다.
  • -?: 하이픈(-)이 있어도 되고 없어도 됩니다.
  • [0-9]{7}: 그 뒤에 숫자 7개가 이어집니다.

앞뒤의 (?<![0-9])와 (?![0-9])는 더 긴 숫자의 일부가 잘못 걸리지 않게 경계를 확인합니다. 따라서 000000-0000000과 0000000000000은 찾고, ******-*******은 찾지 않습니다.

6. 명령의 차단과 통과 비교하기

채팅에서 첫 요청을 실행합니다.

도구 호출의 차단 상태와 사유를 확인한 뒤 둘째 요청을 실행합니다.

첫 호출은 규칙으로 차단되고, 둘째 호출은 ******-*******를 출력하는지 비교합니다. 이 규칙은 명령문 등에 포함된 숫자 모양을 검사합니다. 파일 내용 전체를 검사하거나 실제 주민등록번호의 유효성을 판별하는 기능은 아닙니다.

이어서 보안 → 다층 방어 아키텍처에서 실행 공간, 실행 전 검사, 출력 마스킹·기록이 어느 지점을 보호하는지 살펴봅니다.

8. 승인 대기와 사람의 검토 관찰하기

HITL(Human-in-the-Loop)은 자동화 과정에서 사람이 판단할 지점을 두고 그 결정을 다음 행동에 연결하는 설계입니다. 목적이 모호하거나 실행 결과의 책임이 클 때, 판단에 필요한 내용을 보여주고 사람이 개입할 수 있어야 합니다.

강사가 준비한 Task Runner 화면에서 다음 흐름을 관찰합니다.

  1. 승인 대기: 다음 작업의 실행 시도가 시작되지 않은 상태와 승인·거부 버튼을 확인합니다.
  2. 사람의 검토: 검토할 내용과 실행될 행동을 읽고, 승인할 근거를 말해 봅니다.
  3. 승인 후 진행: 승인 버튼을 누른 뒤 다음 작업이 실행되는지 확인합니다.

질문 카드는 사람에게 업무 기준을 받고, 승인 지점은 다음 행동의 실행 여부를 통제합니다. 관찰할 핵심은 승인 전에는 다음 행동이 실행되지 않고, 승인 후에 진행되는 연결입니다.

직접 시스템을 만들 때 정할 것

  • 누가: 판단할 권한과 책임을 가진 사람은 누구인가?
  • 언제: 업무의 어느 판단 지점에서, 어떤 행동 전에 개입을 요청할 것인가?
  • 판단 근거와 선택지: 어떤 내용·변경점·영향을 보여주고 무엇을 선택하게 할 것인가?
  • 수정과 거부: 수정 요청이나 거부를 받으면 어느 단계로 돌아갈 것인가?
  • 무응답과 재개: 답이 없을 때 어떤 상태로 기다리며, 답을 받은 뒤 어디서 이어갈 것인가?

미션 · 공용 장비 대여 점검
여러분은 학과 장비 대여 담당자입니다. 반납과 연장 요청으로 달라지는 현황을 반복해서 점검하고, 후속 처리에서 사람이 판단해야 할 지점을 정합니다.

앞 실습에서 배운 기능을 사용하되, 이번 작업 지시는 직접 작성합니다. 아래 빈칸에 쓰면서 진행한 뒤 마지막에 제출 기록 파일로 내려받으세요.

9-2. 스케줄에 넣을 지시 직접 작성하기

매번 최신 자료를 읽고 점검 보고서를 만드는 작업을 설계하세요. 아래 질문에 답이 들어가도록 자신의 문장으로 지시를 씁니다.

  • 어디를 읽는가? 내 week06 절대경로와 읽을 파일의 경로가 들어 있는가? 전체 경로는 3-1의 방법으로 확인합니다.
  • 무엇을 점검하는가? 운영 기준에 따라 확인할 상태와 요청, 보고서에 담을 항목을 정했는가?
  • 어느 시점이 기준인가? 운영메모의 업무 기준일시와 실제 실행 시각을 구분했는가?
  • 다시 실행하면? 이전 답을 재사용하지 않고 최신 입력 파일을 다시 읽도록 했는가?
  • 어디에 남기는가? submissions/mission/점검결과.md에 저장하고 실행할 때마다 갱신하도록 했는가?

이 스케줄의 역할은 현황 점검과 보고서 작성입니다. 연장 승인이나 대여 기한 변경은 뒤의 DAG에서 설계합니다.

실습에서는 5분 간격으로 동작을 확인합니다. 특정 시각을 지정했다면 시간대도 적으세요.

직접 작성 → 복사 → Kiro Crew의 스케줄 ‘메시지’ 칸에 붙여 넣습니다. 앱에서 문장을 고쳤다면 이 칸에도 최종 내용을 옮겨 둡니다.

9-3. 스케줄 등록하고 설정 화면 찍기

  1. Kiro Crew의 스케줄 → 작업 추가 → 새 작업을 엽니다.
  2. 이름에는 위에서 정한 작업명을, 메시지에는 직접 작성한 프롬프트를 붙여 넣습니다. 작업 폴더를 고르는 별도 칸은 없으므로 절대경로가 메시지 안에 있는지 확인합니다.
  3. 실행 간격 → 5 → 분, 에이전트 default로 설정합니다. 아래로 내려 승인 항목을 자동 승인으로 선택합니다. 파일 읽기·쓰기 승인을 기다리며 멈추지 않도록 하는 설정입니다.
  4. 메시지와 입력 파일만으로 수행하는 작업이므로 최소 컨텍스트를 켭니다. 만들기로 저장한 뒤 등록된 작업의 상세 화면을 다시 엽니다.

9-4. 첫 결과를 보관한 뒤 다시 실행하기

  1. 첫 예약 실행을 기다리거나 지금 실행을 누릅니다. 채팅 세션의 진행 상황을 보고 완료를 확인합니다.
  2. week06/submissions/mission/점검결과.md를 엽니다. 채팅에 답이 나오는 것과 별도로 이 파일이 실제로 생성되었는지 확인합니다.
  3. 다음 자동 실행 전에 작업을 일시 중지합니다. 점검결과.md를 복사·붙여넣기하고, 복사본 이름을 첫결과.md로 바꿉니다. 원래 파일은 그대로 둡니다.
  4. 변경사항.md를 읽습니다. 편집기에서 practice/mission/대여현황.csv를 직접 열어 지정된 행과 열의 값을 바꾸고 저장합니다. 변경 내용을 프롬프트에 덧붙이는 것이 아니라 입력 파일 자체를 수정합니다.

  6. 완료 후 갱신된 점검결과.md를 복사해 재실행결과.md로 보관하고, 스케줄을 일시 중지합니다.

파일명, 수정한 행의 ID, 열 이름, 변경 전·후 값을 적습니다.

실제로 생성된 두 파일을 읽고, 입력 변경과 연결되는 차이를 적습니다.

9-5. DAG를 만들고 승인 지점 선택하기

이번에는 점검 이후의 후속 처리를 설계합니다. 운영메모와 담당자에게 온 요청을 다시 읽고, 업무를 어떤 단계로 나눌지, 어떤 단계의 실행 전에 사람이 판단해야 할지 정하세요.

지난주 DAG를 만들 때처럼 Kiro Crew 채팅에서 Task Runner 작업 생성을 요청합니다. 아래에 작업 폴더, 읽을 자료, 단계별 할 일과 연결 순서, 각 단계의 결과 파일을 담아 작성합니다. 우선 계획만 만들고, 내가 승인 설정을 마칠 때까지 실행하지 않도록 요청에 명시합니다. DAG에서 수정할 현황은 submissions/mission/ 안의 작업용 사본으로 정해 두면 앞의 비교 결과를 보존할 수 있습니다.

직접 작성 → 복사 → Kiro Crew 채팅 입력창에 붙여 넣습니다. 이 문장은 스케줄 메시지와 별개입니다.

  1. 생성된 Task Runner 작업을 열고 단계별 할 일과 순서를 확인합니다. 의도와 다르면 채팅에서 수정을 요청합니다.
  2. 실행 전에 승인 설정에서 내가 선택한 단계에 승인 필요를 켭니다. 아래 사진에서 체크 위치를 확인하세요.
  3. 단계 이름과 승인 설정이 함께 보이도록 DAG_HITL.png를 찍고 submissions/mission/에 저장합니다.
  4. 그 단계의 행동과 사람이 판단해야 하는 이유를 아래에 적습니다. 이 미션에서는 승인 지점의 설정과 이유를 제출합니다.

어떤 자료나 상태를 어떻게 바꾸는지, 승인하면 무엇이 실행되는지 적습니다.

업무 기준과 요청의 어떤 부분을 사람이 판단해야 하는지 설명합니다. 여러 단계에 설정했다면 단계 이름별로 행동과 이유를 구분합니다.

  1. 다운로드된 제출기록.md를 다운로드 폴더에서 찾습니다. 저장 위치를 물으면 처음부터 week06/submissions/mission/을 선택해도 됩니다.
  2. week06/submissions/mission/제출기록.md가 빈 양식이면 내려받은 파일로 교체합니다. 이미 작성한 내용이 있다면 먼저 두 파일을 열어 필요한 내용을 합친 뒤 저장합니다.
  3. 최종 파일 이름을 제출기록.md로 맞춥니다. 이름에 (1) 등이 붙지 않았는지, 파일을 열었을 때 직접 작성한 문장이 들어 있는지 확인합니다.
