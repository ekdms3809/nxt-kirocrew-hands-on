# 6주차 · 스케줄, 병렬 위임, 가드레일과 사람의 결정

정원 12명의 학과 AI 실습 모임을 준비합니다. 신청과 취소로 달라지는 인원과 남은 자리를 매일 확인하고, 외국인 유학생 친구에게 전달할 안내를 영어·일본어로 작성합니다. 안내의 독자와 분량은 사람이 선택합니다.

## 시작

먼저 [시작하기.html](시작하기.html)을 브라우저로 여세요. 기존 주차와 같은 단계별 안내, 요청문 복사 버튼, 완료 체크를 사용할 수 있습니다. Kiro Crew의 작업 폴더는 이 `week06` 폴더로 맞춥니다.
병렬 위임 전에는 시작하기의 **실행 전 설정**에서 최소 여유 메모리 기준을 1 GB로 맞춥니다.

```text
week06/
├── README.md
├── 시작하기.html
├── assets/mission/           # 미션 작성 기능과 앱 화면 안내
├── practice/
│   ├── 모임조건.md
│   ├── 신청현황.csv
│   ├── 모임안내_원문.md
│   └── mission/
│       ├── 운영메모.md
│       ├── 대여현황.csv
│       ├── 담당자에게_온_요청.md
│       └── 변경사항.md
└── submissions/
    ├── schedule/            # 정기 점검 결과
    ├── parallel/            # 언어별 번역과 부모의 종합
    ├── hitl/                # 사람의 선택 기록
    └── mission/             # 미션 제출 파일
        └── 제출기록.md       # 작성할 제출 양식
```

## 실습 흐름

1. **스케줄:** 5분 간격·자동 승인으로 신청 현황 점검을 등록합니다. 첫 실행 뒤 신청 2명을 추가하고 1명을 취소로 바꿔 재실행 결과를 확인합니다.
2. **병렬 위임:** 영어·일본어를 두 서브에이전트에 맡기고, 두 작업이 끝나면 결과를 종합합니다.
3. **가드레일:** 숫자 문자열이 포함된 명령의 차단과 마스킹 후 실행을 비교합니다.
4. **질문 카드 체험:** 처음 참가자를 위한 상세 안내와 기존 참가자를 위한 핵심 안내 중 하나를 고릅니다.
5. **승인 흐름 관찰:** 강사가 준비한 Task Runner 화면에서 승인 대기 → 사람의 검토 → 승인 후 진행을 확인하고, 직접 만드는 시스템의 사람 개입 지점을 생각합니다.
6. **공용 장비 대여 미션:** `practice/mission/`의 자료로 스케줄 프롬프트와 DAG 승인 지점을 직접 설계합니다. 첫 결과를 보관한 뒤 `변경사항.md`에 따라 현황 파일을 수정해 비교합니다.

W05에서 만든 DAG를 스케줄로 등록하는 시연은 W05의 기존 작업을 사용합니다. 이 폴더에서는 스케줄 뷰에서 직접 만드는 신청 현황 점검을 수행합니다.

입력 자료는 `practice/`에, 자신이 실행해 만든 결과는 `submissions/`에 둡니다.

## 결과 확인

| 단계 | 확인할 결과 |
|---|---|
| 스케줄 | `submissions/schedule/신청요약.md` — 신청·취소 인원, 남은 자리, 신청 마감까지 남은 기간 |
| 병렬 번역 | `submissions/parallel/영어.md`, `일본어.md` |
| 부모 종합 | `submissions/parallel/다국어안내.md` |
| 사람의 선택 | `submissions/hitl/선택기록.md` |
| 승인 흐름 관찰 | 강사 화면에서 승인 전 대기와 승인 후 진행 |

신청 현황은 처음에 **신청 7명·취소 1명·남은 자리 5석**입니다. 시작하기의 변경 절차를 따라 다시 실행하면 **신청 8명·취소 2명·남은 자리 4석**으로 바뀝니다. 마감까지 남은 기간은 실행한 실제 한국 시각을 기준으로 계산합니다.

가드레일 실습은 도구 호출의 차단·실행 화면을 확인합니다. 등록한 스케줄은 결과 확인을 마치면 일시 중지합니다.

## 미션 제출 경로

먼저 [시작하기 9번](시작하기.html#mission-submission)을 따라 자료 읽기 → 지시 작성 → 스케줄 등록·촬영 → 결과 비교 → DAG·HITL → 제출 순서로 진행합니다. 프롬프트와 비교 기록, HITL 선택 이유를 페이지의 빈칸에 직접 쓰고 `제출기록.md`로 다운로드할 수 있습니다. 작성 내용의 브라우저 임시 저장과 제출 파일 저장은 별개이므로, 내려받은 파일을 아래 폴더에 옮깁니다.

미션의 제출 파일은 이 `week06` 폴더 아래 **`submissions/mission/`**에 모읍니다. [제출기록.md](submissions/mission/제출기록.md)에 실제 등록한 스케줄 프롬프트, 변경한 데이터와 결과의 차이, DAG에서 승인 필요로 설정한 단계와 이유를 적으세요.

```text
submissions/mission/
├── 제출기록.md
├── 스케줄설정.png
├── 첫결과.md
├── 재실행결과.md
└── DAG_HITL.png
```

실행 결과는 `submissions/mission/점검결과.md`를 매번 갱신하도록 지정합니다. 첫 실행 뒤 `첫결과.md`로 복사해 보관한 다음 데이터를 바꾸고 재실행하세요. 재실행 뒤에는 갱신된 결과를 `재실행결과.md`로 복사합니다. 위 목록 중 제출 양식만 미리 들어 있으며, 결과 파일과 스크린샷은 직접 실행하면서 추가합니다.

저장·복사 순서는 [시작하기의 제출 안내](시작하기.html#mission-submission)에서 확인할 수 있습니다.

완성한 5개 파일을 본인 GitHub 실습 저장소의 `main`에 커밋·푸시한 뒤, 웹에서 `class/kookmin-2026-2/ai-platform-development/week06/submissions/mission/`을 열어 확인합니다.
