# 따라하기 · 창고 재고 점검

세 창고의 재고를 정리해 구매 담당자에게 전달하는 상황입니다. 한 번 실행한 결과가 요청과 일치하는지 확인하고, 명세를 보완해 다시 실행합니다.

## 입력

[data/warehouse-a.md](data/warehouse-a.md), [warehouse-b.md](data/warehouse-b.md), [warehouse-c.md](data/warehouse-c.md)를 사용합니다. 세 파일의 재고 기준 시점과 단위는 같으며 수량은 개입니다. 표에 없는 창고·품목 조합을 새로 만들거나 0으로 추가하지 않습니다.

## 진행 자료

- [첫 업무 요청](업무요청.md): 모호한 표현을 먼저 찾아봅니다.
- [출력 형식](출력형식.md): JSON과 짧은 보고서의 구조를 확인합니다.
- [명세 구성 참고](명세_틀.md): 정제된 명세에서 확인할 항목을 살펴봅니다.
- [검증 예제](cases/README.md): 강사의 안내 후 정상·오류 결과를 비교합니다.
- [경계값 자료](tests/README.md): 별도 입력으로 5 미만의 경계를 확인합니다.

1차에서는 별도 초안 파일을 쓰지 않고, 시작하기 2번의 제공 프롬프트를 입력해 명세로 다듬습니다. 정제된 명세에 **창고별 행의 수량이 5 미만**이라는 기준이 남았는지 확인하세요. 2차 업무에서는 구매 담당자의 요청에 따라 **전체 창고의 품목별 총수량이 5 미만인 품목**을 저재고로 정합니다. 같은 원본으로 재실행하고 달라진 부분을 비교합니다.

## 결과와 확인

week05/submissions/practice 안에 실행별 폴더를 나누어 명세, result.json, 짧은 보고서, 검증 기록을 저장합니다. 만든 코드도 같은 폴더에 보관할 수 있습니다. 현재 실행에서 새로 만들어진 결과인지 확인하세요.

제공하는 검사는 2차 업무의 전체 품목별 기준용입니다. week05 폴더의 터미널에서 다음과 같이 실행합니다. python3 대신 python을 사용하는 환경에서는 실행 이름만 바꾸세요.

```sh
python3 practice/tests/check_result.py submissions/practice/run02/result.json
```

이 검사는 원본에서 수치를 다시 계산해 JSON과 비교합니다. Markdown 보고서의 내용, 실제 Task Runner 실행 여부, 입력 미변경, 종료 후 최종 폴더에 저장됐는지까지 증명하지는 않습니다. 이 항목은 별도로 대조해 기록하세요.
