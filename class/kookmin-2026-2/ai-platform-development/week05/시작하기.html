1. 실습 폴더 준비

이 HTML만 옮기지 말고 week05 폴더 전체를 내려받아 압축을 풉니다. 모든 상황과 자료는 수업용 가상 자료입니다.

  • 따라하기 입력 자료: practice
  • 독립 미션 입력 자료: mission
  • 제출 기록: 검증 기록 틀

Kiro Crew에서 Task Runner를 열고, 워크스페이스 폴더에 내 컴퓨터의 week05 절대경로를 입력하세요. 기본 폴더로 두지 않습니다. 따라하기와 미션 모두 week05를 사용합니다. 입력은 practice와 mission에 두고, 결과는 같은 수준의 submissions/practice와 submissions/mission에 저장합니다. 생성된 계획의 작업 폴더도 다시 확인하세요. Agent는 실행할 에이전트를 선택하는 항목입니다. Git 저장소 안에서는 별도 브랜치와 worktree를 사용할 수 있으므로, 실행 로그의 실제 경로와 결과 브랜치를 확인하세요. 원래 체크아웃에 결과가 바로 나타난다고 가정하지 않습니다. 기존 실행을 재개하면 처음의 작업 위치를 사용합니다.

practice/data의 창고 파일 3개를 직접 열어봅니다. 입력은 보존하고 결과는 submissions/practice/run01, submissions/practice/run02로 나눕니다.

2. 모호한 요청을 명세로 바꾸기

practice/업무요청.md를 열어 읽고 모호한 기준을 함께 살펴봅니다. 별도 초안 파일은 작성하지 않습니다. 강사의 안내에 따라 아래 제공 프롬프트를 입력하고, 다듬어진 명세를 검토하세요.

첫 업무 요청에서 ‘저재고’의 기준을 찾아보세요. 창고별 행의 수량과 전체 창고를 합친 품목 수량은 다릅니다. 이번 따라하기 1차에서는 창고별 행을 기준으로 정합니다.

출력 형식을 확인한 뒤 ‘작성’의 작업 설명에 아래 내용을 넣고 명세로 다듬기를 선택합니다.

다듬은 명세에서 입력 파일, 저재고 단위, 5 미만 조건, 저장 위치, 완료 조건을 읽습니다. 자신의 의도와 다르면 계획을 만들기 전에 수정하세요. ‘명세로 다듬기’는 입력문을 구조화하는 기능이며 원본 파일을 읽고 검증하는 단계는 아닙니다. 이번 실습에서는 정제된 명세로 계획을 만든 뒤 실제 실행을 시작합니다.

3. 실행 계획 확인과 실행

명세로 플랜 만들기로 계획을 생성합니다. 생성된 노드와 선행 관계를 읽고 다음 내용을 설명해 보세요.

  • 집계가 어떤 입력 읽기에 의존하나요?
  • 보고서와 검증은 어떤 결과가 먼저 필요하나요?
  • 독립적으로 처리 가능한 구간이 있나요? 순차라면 이유는 무엇인가요?

원본 파일 수와 노드 수는 같을 필요가 없습니다. 계획과 작업 폴더를 확인한 후 실행합니다. ‘도구 호출 자동 승인’은 켜지 않고, 승인 요청이 나타나면 대상 경로와 명령을 확인합니다.

진행이 멈춘 것처럼 보이면 상단 알림을 확인하세요. ‘도구 승인’ 알림을 열어 파일 경로와 변경 내용을 읽고 요청 범위와 맞을 때 승인합니다. 실행 완료 표시를 확인한 다음에도 실제 파일을 다시 열어야 합니다. 생성되는 노드 이름과 개수는 실행마다 달라질 수 있습니다. DAG 보기에서는 선행 관계를, 단계별 보기에서는 작업 상태를 확인합니다. 일시 중지 후 재개는 이어서 실행하는 기능이고, 다시 실행은 전체 작업을 반복할 수 있습니다. 취소해도 이미 바꾼 파일이나 외부 작업이 자동으로 복원되지는 않으므로 재실행 전에 현재 결과를 확인하세요.

4. 결과와 원본 대조

submissions/practice/run01을 열고 명세, 계산 코드, JSON, 보고서, 검증 기록이 저장되었는지 확인하세요.

  • 창고별 합계와 품목별 합계의 총합이 일치하는가?
  • 원본에 등장한 모든 품목이 결과에 있는가?
  • 저재고 목록이 1차 명세의 창고별 행 기준과 일치하는가?
  • JSON과 Markdown 보고서의 수치가 같은가?
  • 원본 파일이 바뀌지 않았는가?

제공된 검증 예제는 실제 실행 결과와 별개입니다. error-d.json처럼 전체 합계가 맞아도 품목별 값이 틀릴 수 있습니다.

제공 검사기는 2차의 전체 품목 합계 기준 전용입니다. 1차 결과를 이 검사기로 판정해 계산 오류라고 결론 내리지 마세요.

5. 기준 수정과 재실행

새 작업에서 같은 week05 작업 폴더를 지정합니다. 1차 결과를 보존하고, 이번에는 전체 창고의 품목별 총수량을 저재고 기준으로 사용합니다.

명세와 실행 계획을 다시 검토하고 실행합니다. 종료 후 실행 로그에서 확인한 실제 작업 위치의 week05 폴더 터미널에서 검사 명령을 직접 재실행하세요.

Python 실행 이름이 python인 환경에서는 실행 이름만 바꿉니다. 5 미만과 5 이하를 구분하고, 기본 창고 데이터와 경계값 데이터의 결과를 섞지 않습니다.

6. 독립 미션 · 공지 6건 브리핑

미션 안내를 읽고 직접 명세와 실행 계획을 만듭니다. 새 작업의 워크스페이스도 week05입니다. 입력은 mission/data, 결과는 submissions/mission입니다.

기준 시각은 2026-09-14 09:00, Asia/Seoul입니다. 컴퓨터의 오늘 날짜를 사용하지 않습니다. 공지 원문 6건을 모두 검토하세요.

  • 대상 독자와 분류·포함·제외·정정 처리 기준을 직접 정합니다.
  • N01–N06의 처리 결과와 이유를 남깁니다. 최종 항목 수는 고정하지 않습니다.
  • 입력 ID 전수 처리와 출력 출처 ID 유효성 검사를 포함해 자동 검사 3개 이상을 만듭니다.
  • 원문 대조 1개 이상과 오류 개선 사례 1개를 기록합니다.
  • 첫 결과에 오류가 없다면 결과 복사본에 누락을 넣어 검사 검출을 확인하고, 복원 후 재검사합니다. 이를 실제 실행에서 발생한 오류와 구분해 적습니다.

원문에 없는 날짜·시각·링크는 만들지 않습니다. 실제 발송·게시 없이 브리핑 파일과 검증 기록을 submissions/mission에 저장합니다.

7. 최종 확인과 제출

종료 후 결과를 다시 열고 다음 항목을 확인합니다. 강사가 안내한 제출 위치에 결과와 기록을 제출하세요.

체크 표시는 제출 증거가 아니며 페이지를 새로 열면 초기화됩니다. 검증 기록 파일에 확인 내용을 남기세요.
