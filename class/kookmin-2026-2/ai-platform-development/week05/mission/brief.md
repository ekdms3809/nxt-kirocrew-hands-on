# 독립 미션 · 캠퍼스 공지 브리핑

NXT대학교 학생회 운영진이 학생들에게 제공할 공지 브리핑 초안을 준비합니다. 모든 기관·행사·공지 내용은 수업용 가상 자료입니다.

## 업무 상황

기준 시각은 **2026-09-14 09:00, Asia/Seoul**입니다. 실제 수업일이나 컴퓨터의 현재 시각을 사용하지 마세요.

[data/notices.md](data/notices.md)에 있는 공지 6건을 모두 검토하세요. 학생에게 필요한 내용을 골라 분류·요약하고, 원문을 찾아갈 수 있는 브리핑을 만드세요. 실제 발송이나 외부 게시 없이 파일로 저장하는 작업입니다.

## 직접 정할 것

대상 독자, 분류 체계, 포함·제외 기준, 정정·병합 처리 방식, 실행 계획과 추가 검사 조건을 정하세요. 입력 파일의 개수가 작업 노드 수를 결정하지 않습니다. 앞 단계 결과가 필요한 작업과 독립 처리할 수 있는 작업을 설명할 수 있어야 합니다.

원문에 없는 날짜·시간·링크를 만들지 마세요. 정보가 부족하면 그 사실과 확인할 내용을 남기세요. 출처는 파일명과 공지 ID로 연결합니다.

## 완료 조건

- 실행 전에 작업 명세와 통과 기준을 작성합니다.
- N01–N06 모두 포함·병합·제외 중 어디로 처리했는지와 이유를 남깁니다. 최종 브리핑 항목 수는 기준에 따라 달라질 수 있습니다.
- 일정·마감·변경 내용을 원문에 맞게 반영하고, 출처가 추적되는 브리핑을 만듭니다. HTML 또는 Markdown을 사용할 수 있습니다. data-to-html 스킬 재사용도 가능합니다.
- 자동 검사 3개 이상과 원문 대조 기록 1개 이상을 남깁니다. 입력 ID 전수 처리와 출력의 출처 ID 유효성은 반드시 검사하고, 추가 조건은 직접 정합니다.
- 실제 실행 계획을 확인하고 선행 관계와 독립 처리 가능 구간을 설명합니다. 계획이 순차여도 이유를 설명할 수 있으면 됩니다.
- 오류 개선 사례 1건을 기록합니다. 첫 실행에 오류가 없다면 결과 복사본에 누락 등을 넣어 검사가 잡는지 확인하고, 복원 후 재검사합니다. 원본 공지는 수정하지 않습니다.
- 작업 종료 후 최종 폴더에서 결과를 다시 열고 명세·실행·검증 기록과 함께 제출합니다.

파일 이름이나 개수보다 결과와 증거를 확인합니다. week05/submissions/mission 안에서 실행별 결과를 구분하세요. 미해결 조건은 숨기지 말고 미완료로 적습니다. 검증을 통과한 최종 결과가 있어야 완수입니다.
